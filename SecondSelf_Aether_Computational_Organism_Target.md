# SecondSelf / Aether Computational Organism Target

This repository should preserve prompts that reinforce the same architecture used by the implementation repositories rather than teaching agents incompatible mental models.

Core statement: **SecondSelf is the understanding and the Method. Aether Digital Monad is the way.**

SecondSelf governs meaning, identity, values, constraints and acceptable success. Aether relentlessly but boundedly seeks lawful capability, optimization and execution paths.

When prompting builders, researchers or external AI, preserve these design targets:

1. Use one shared L0-L3 capability-memory physics: L0 executable reflex, L1 hot mature capability, L2 reusable learned capability, L3 deep reconstructable experience/evidence.
2. Prefer semantic firing/reuse before expensive recomputation. Exact reuse, safe deterministic transformation and cached verified capability outrank fresh model generation.
3. Treat negative knowledge/scars as inhibitors so known failed routes are not repeatedly rediscovered.
4. CSX targets dense cache-near executable motifs and measured capability per byte; musical-score ideas survive only where they produce real compression/locality/execution advantage.
5. SRWL owns adaptive semantic weighting/active state, primarily RAM + CPU/SIMD.
6. MICO owns hardware lowering/fusion across CPU, SIMD, GPU, NPU, WASM and admitted accelerators.
7. Ariadne owns durable experience/scars/reuse chronology.
8. Centipede exposes distributed capability/Fingers without becoming a second scheduler or resource authority.
9. Code Forge uses the whole organism: cache/repository intelligence/deterministic machinery first, heterogeneous AI Fingers only for unresolved novelty, authoritative verification, deterministic selection and serialized repository mutation.
10. `modelRouter` and canonical registry remain sole live model/provider routing authority; canonical resource admission remains singular; model/provider output never self-certifies truth.
11. Aether continuously looks for lawful/free/cheap useful Fingers and tools, then sandboxes, benchmarks, behaviorally characterizes and compares them before canonical admission. Do not hard-code one runtime/provider as the architecture.
12. Convert expensive intelligence into cheaper reusable machinery whenever evidence supports it: external AI -> local/specialist -> procedure -> template -> algorithm -> CSX motif -> cache reflex.
13. Every proposed new organ must pass an originality test and declare OWN/BORROW/FORBIDDEN boundaries so the number of authority and resource collisions decreases as the system grows.
14. Judge improvement by evidence: correctness, latency, memory, energy, bytes, cost, restart behavior, cache fire/reuse yield, execution depth, Finger regret and collision rate.
15. UNKNOWN is never PASS. Design intent is not runtime proof.

A strong research/build prompt should ask not only "how do we solve this?" but also:

- Can the solution already fire from verified capability memory?
- What is genuinely novel here?
- What is the cheapest capability tier able to solve the unresolved portion?
- Which heterogeneous Finger is empirically best for that portion?
- What behavior/failure should be predicted before assignment?
- What can be compiled, compressed, cached or turned deterministic after success?
- Can the next materially equivalent obligation avoid the expensive intelligence used this time?
- Does the proposal duplicate an existing canonical authority?
- What executable evidence would falsify the claimed improvement?

The decisive vertical target is a real obligation that initially requires novel intelligence, verifies successfully, is converted into reusable deterministic/CSX capability, and later completes a materially equivalent obligation from cache/reconstruction without the original expensive model call while still passing authoritative verification.
